# Интеграция upstream 2.5 в отдельной ветке

Ветка `feature/upstream-2.5-all`, версия `2.5.0-dev.1`.
Исходная точка форка: `5c3cf032dade852a92bf1f2cf2bc6cd7008c428c`.
Основа переноса: upstream `fd936ef087c34cc46f26111dc2361f43b8b03c07`
(последующий `d02da9b` не содержит нового transport-кода).

## Что перенесено

- Новый Rust transport, DTLS-SRTP с WRAP/auto, фрагментация и сборка пакетов,
  dispatcher, распределение потоков, TURN IP pool, UDP и TCP/TLS.
- Серверные группы, подписки, массовые операции, domain/IP routing,
  настройки DNS, IPv6, web secret path и обновлённая веб-панель.
- Android domain/IP routing, настройки TURN и SRTP, виджет и QR workflow.
- Десять именованных Android-профилей для владельца и участника. Переключение
  профиля сохраняет роль; данные разных слотов остаются независимыми.
- Раздельные списки приложений для обхода VPN и whitelist. Последняя правка
  списка сохраняется и при немедленном закрытии вкладки.
- Нативный SOCKS5 сохранён на новом transport: loopback по умолчанию,
  LAN только с RFC1929-авторизацией, ограниченные handshake и число сокетов.
- Ограничение TCP/TLS TURN write одной секундой: при частичной записи и
  таймауте соединение закрывается, счётчик доступен как `turn_write_stalls`.
- OpenWrt: нативный TUN/hook, прежние fw4/iptables и include/exclude policies,
  новые SRTP/TURN/domain/IP параметры, пароль SOCKS через credentials stdin.

## Намеренные несовместимости

Эта ветка требует одновременного обновления наших клиентов и сервера.
`GETCONF` явно помечен `CSQTT-WIRE-4`; старые форматы отвергаются, разбор
числового пароля не зависит от эвристик. Это собственный протокол форка,
он не обещает подключения нового клиента к серверу upstream 2.5.

Серверная модель upstream идентифицирует подключение паролем и epoch.
Прежняя модель устройств этого форка не сохраняется: двум независимым
одновременным клиентам следует выдавать разные пароли. Старую конфигурацию
сервера перед будущим развёртыванием нужно сохранить и проверить отдельно.
Автоматическая миграция production-базы и откат не проверялись.

## Сохранённые свойства форка

Package ID `io.github.danusha2345.csqtt`, подпись, защищённый updater,
TOFU SSH и sudo stdin при установке сервера. Connection password, CSQTT link,
VK token и SOCKS password хранятся через Android Keystore. Экспорт по
умолчанию не включает секреты; их включение требует отдельной галочки.
Импорт ограничен размером/версией, проверяется до атомарной записи и
применяется к выбранному профилю, а не всегда к нулевому.

Дескрипторы Android TUN принимаются только от того же UID или root.
Сборка APK проверяет ELF-архитектуры и SHA-256, актуальность native inputs,
версию сервера и wire marker. Встроенные серверы собираются статически musl
для amd64/arm64/armv7. PS и Python provenance используют одинаковые inputs.

## Исправления, найденные при интеграции и ревью

- SOCKS5 DATA на сервере больше не передаются независимым concurrent tasks:
  они попадают в очередь в порядке поступления. Иначе локальный DTLS E2E
  воспроизводил обрыв TCP из-за reorder даже без потерь сети.
- `msg_controllen/cmsg_len` учитывают ABI glibc и musl; ancillary header
  читается без предположения о выравнивании.
- Инициализация SettingsStore запускается после объявления Flow.
- Android secrets не мигрируют в plaintext upstream.
- Обновлённые shared/native vendor sources включены в provenance.
- Desktop устанавливает bypass заданных TURN IPv4 до VPN routes;
  IPv6/hostname в этом поле отклоняются, поскольку текущий bridge IPv4.

## Локальная проверка transport

После сборки Linux-сервера:

```bash
CSQTT_LOCAL_E2E_SERVER=/absolute/path/to/csqtt \
CARGO_TARGET_DIR=/path/to/build-cache bash scripts/test_local_transport.sh
```

Скрипт проверяет отдельный network namespace до изменения сети. Использует
локальный TURN relay с синтетическими credentials и настоящий сервер.
Оба режима WRAP и DTLS проверяют handshake, назначение адреса, ICMP,
фрагментированный пакет 1480 байт, SOCKS5 RFC1929 CONNECT и возврат 4096 байт.
VPS, VK API и сеть хоста не затрагиваются.

Это не проверка реального VK TURN, DPI провайдера, игр, Windows UAC,
Android VPN на телефоне или OpenWrt на физическом роутере. Жалобы upstream
на потерю workers и игровые проблемы нельзя считать полностью закрытыми
по этим локальным тестам. Изменения из незамерженных PR не считаются
принятыми upstream только потому, что они обсуждались в issues.

Публикация и деплой этой ветки не выполнялись.

Дополнительные исправления ревью: участник с невалидными hash в ссылке не
переключается молча на звонок владельца; секретный путь панели создаётся и
сохраняется до передачи installer; импорт пути относится к выбранному профилю.
Секретный путь исключён из экспорта без галочки секретов. PowerShell provenance
делегирует общей Python-реализации, исключая расхождения списков/порядка inputs.

Проверка APK обнаружила конфликт двух Bouncy Castle (`jdk15to18:1.78.1` и
`jdk18on:1.85`): воспроизведён провал `checkDebugDuplicateClasses`. Оставлена
единая линейка `jdk18on:1.85` и единый Compose BOM `2026.08.00`.

## DTLS: дополнительное исправление итогового ревью

Upstream не закрепляет случайный сертификат DTLS. Одни exporter keys не
аутентифицируют сервер: подставной peer знает их и мог читать GETCONF с паролем.
Это подтверждено отрицательным тестом: до исправления регистрация под сырыми
exporter keys принималась, после исправления отклоняется.

`password_bound_cipher_keys` использует TLS 1.2 PRF: secret — производный ключ
пароля, seed — оба DTLS cipher keys, отдельный label
`CSQTT-WIRE-4 DTLS password binding`, раздельные результаты для направлений.
Клиент и сервер используют эти ключи для регистрации и последующего трафика.
Регистрация через DTLS application data без этой привязки не принимается.
Самоподписанный сертификат по-прежнему не считается проверенной идентичностью;
проверка пароля осуществляется аутентификацией кадров и ответом TUNCONF.

После изменения: client 371 passed/11 ignored, server 154 passed/1 ignored,
Clippy обоих crates без предупреждений; локальный WRAP/DTLS/SOCKS5 E2E проходит.
APK сохраняет объединённые LICENSE.md зависимостей; неиспользуемые Android
OSGi-манифесты исключены из упаковки.

  успешны. Универсальный APK и три ABI APK подписаны одним сертификатом,

по запросу пользователя. Публикация, деплой и установка на устройства не
выполнялись; реальный VK TURN, Windows VPN/UAC runtime и физические Android/
OpenWrt устройства не проверены этим локальным прогоном.
